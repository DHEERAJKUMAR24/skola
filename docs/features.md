# Features by module

- **Floating create button (every screen except study):** bottom-right, opens New card (current deck, else the last deck used, else the first), New deck, and New sub-deck when a deck is open. `src/app/shell/CreateFab.tsx`.
- **Home:** deck tree, per-deck counts (review / new / learning), create deck (name, description, color, preset, exam date).
- **Deck page:** hero study button, exam panel (cards on track), sub-decks, edit, move, rename, menu.
- **Deck color picker:** radio group, named swatches, check mark on selection.
- **Study session:** Again/Hard/Good/Easy (Hard/Easy can be hidden), daily limits, cram and learn-all modes, leech and sibling rules.
- **Card controls:** card scheduling modal (due date, suspend, bury, reset), card menu in the editor.
- **Connect an AI assistant:** one page, `/skills`, with the MCP address, per-assistant steps and skill install commands (copy buttons everywhere), generated from the same source as `/llms.txt` for agents; app profile menu links to it and copies the address.
- **Pictures:** shrunk in the browser, kept on the device, uploaded to R2 in the background, referenced as `media:<sha256>`; work offline; fall back to inline when R2 is off.
- **Card types:** basic, reverse, cloze, multiple choice, list recall and image occlusion; `src/logic/type-implementations/*`, editors in `src/app/editor/NoteEditor/`. Over MCP, `add_cards` makes all six types: basic, reverse (same note and two cards as the app editor), cloze, multiple choice, list and image occlusion (image occlusion from a public https link or base64, under 400 KB), `edit_card` edits every type, and `get_card_image` returns an image-occlusion picture.
- **MCP parity:** the app's deck menu, presets and limits, notes explorer, card scheduling dialog and View details are also MCP tools (`src/server/mcpManage.ts`: get_deck, update_deck, delete_deck, list_presets, update_preset, list_cards, list_tags, get_card_details, deck_schedule, set_card_schedule, move_cards, delete_cards, bulk_update_cards, card_history, restore_card_version); studying is `src/server/mcpStudy.ts` (sessions with show_answer and idempotent submit_review). Deletes need a two-step confirm token.
- **Settings sidebar:** Settings has a second sidebar (`src/app/settings/sections.ts`, `SettingsView.tsx`) in groups: App, Studying, AI assistants (Instructions, Connect, Skills), Data, More. Routes are `/settings/:section/:item?`; Connect and Skills (the skill editor) are in-app pages (`src/app/skills/`) that use the app's own sign-in. The same guide is a public server-rendered page at `/skills` (+ `/skills/[name]`, raw files, zips) and plain text for AI agents at `/skills/llm.txt` (alias `/skills/llms.txt`, also `/llms.txt`, `/llms-skill.txt`); `/skills/edit` redirects to the in-app editor.
- **AI assistant instructions:** Settings, AI assistants tab (`src/app/settings/AiSettingsView.tsx`) holds a synced free-text setting `#aiInstructions` (max 4000 chars). Never saved means the built-in default (`DEFAULT_AI_INSTRUCTIONS`) is shown and used; text cleared on purpose stays empty; "Reset to the default instructions" (or `set_instructions` mode reset) deletes the setting so the default returns. The MCP server puts the first 1500 chars in the session start text (`<user_instructions>`) and serves all of it with `get_instructions`; `set_instructions` appends, replaces or resets. Rules in `src/logic/settings/aiInstructions.ts`; server in `src/server/mcpInstructions.ts`.
- **Edit history:** each note keeps its previous version for 7 days, never empty for an old note, no cron (`src/server/noteHistory.ts`, ADR 0011). In the app: **History** in the note menu and the card menu (`src/app/editor/NoteHistoryModal.tsx`) lists the saved versions, compares each with the text now word by word (green is in the version, red is in the text now) and has a Restore button; it needs sign-in and a connection and says so otherwise ("History needs sign-in and a connection"). Unsent edits are pushed first, a restore saves the current text first and the app pulls the result. Over MCP: `card_history` (also returns `current`) and `restore_card_version`. The app calls `/api/history` (`app/api/history/route.ts`), which runs the same tool functions through `src/server/appApi.ts`.
- **Learning objectives (app and MCP):** objectives with Knowledge and Skill ratings and mastery rules (`src/logic/learning/mastery.ts`, `src/server/mcpEvidence.ts`, ADR 0012). App page `/objectives` (sidebar entry Objectives, `src/app/objectives/`): list with status filter, priority, mastery, K and S score and the eight latest ratings; detail with what blocks mastery, per-dimension table, full assessment history, linked cards (link and unlink by searching local cards), edit, delete (two steps: preview of what goes, then confirm) and a manual assessment form that shows the server's checks (`src/logic/learning/assessmentForm.ts`, kept in step by a test). The data is server-only, so the page needs sign-in and a connection. Backend `/api/objectives` runs the MCP tools through `src/server/appApi.ts`. Five default skills route assistants (`skola`, tutor, architect, maintainer, auditor).
- **Master card (core, UI first, ADR 0014):** note type `master` (`src/logic/type-implementations/master/`, editor `src/app/editor/NoteEditor/MasterCardEditor.tsx`): a name, sections, entries (text plus optional card id). One study card for the whole master up to 12 entries; above 12 entries and with two or more sections, one card per top-level section (`planMasterCards`). Cards that the plan drops are deleted when never reviewed, else suspended and marked `retired`; they return when wanted again. Pure engines in `src/logic/master/` (no Dexie, reusable by the server): `masterModel.ts` (model, clean, validate, `parseMasterText`/`masterToText`, plan), `coverage.ts` (`analyzeCoverage`: orphan, dangling, empty, unlinked, stale, duplicate entries), `suggestRating.ts` (`suggestMasterRating` from the linked cards' FSRS state). Dexie side `masterCards.ts` (`syncMasterCards`, `coverageOfMaster`, `linkedStatesOf`, `createMasterFromDeck`). In study the answer shows the entries and a "Suggested rating" badge; the user rates with the normal buttons. The notes explorer view shows the entries and a coverage summary. Deck menu, "Create Master Card" makes a master with one linked entry per card. A card picker (`src/app/master/CardPickerModal.tsx`) links an entry to any card of any deck. MCP tools (built 2026-11-06, `src/server/mcpMaster.ts`, tests `mcpMaster.test.ts`): `create_master_card` (written sections, or `from_deck` grouped by tag with `dry_run` preview; `idempotency_key` gives deterministic ids), `get_master_card`, `list_master_cards`, `update_master_card` (ops: sections and entries add, rename, move, remove, link, unlink, add orphan cards, remove dangling entries; the study cards follow `planMasterCards` like `syncMasterCards`), `master_coverage` (report plus ready `fix_ops`), `suggest_master_rating`, `delete_master_card` (confirm token). Replies carry `labels` with the user's `#hierarchy` names. Other tools know the type: search and list read entry text, study sessions ask a recall question and show entries plus a suggested rating on `show_answer`, `edit_card` points to `update_master_card`, `delete_cards` refuses a master's study cards, `get_card_details` and `cardView` carry a `master` object, `restore_card_version` re-plans the cards, `find_similar_cards` skips masters. **`get_master_card` was repurposed:** it used to be a deprecated alias of `get_objective_overview`; the alias is removed and an `objective_id` call returns `[renamed_tool]`. Not built yet: full builder, graph view, activities (other work).
- **Knowledge hierarchy (Settings, Studying, Hierarchy):** synced setting `#hierarchy`, list of levels with roles deck, master, section, entry. Default Domain (deck), Subject (deck), Chapter (section), Concept (entry). Rules in `src/logic/settings/hierarchy.ts` (pure); page `src/app/settings/HierarchySettingsView.tsx`; the editor uses the level names. `hierarchyInstructions()` gives assistants a one-paragraph description.
- **Notes explorer:** search, filter, tags, bulk bar (move, tag, suspend), note tags editor.
- **Settings pages (in the sidebar above):** General, Appearance, Editing, Learning (global scheduler fallback), Study presets, AI assistants (Instructions, Connect, Skills), Database, Account (sync, push delay), About, Developer.
- **Profile menu / avatar:** sync status with push countdown ring, Sync now, Account settings, Take a tour of this page, sign in/out.
- **Tooltips:** `InfoTip` (hover, focus, tap, Escape) rendered with the Popover API so it sits above modal dialogs; `LabelWithTip` for form labels. Used on the preset and deck forms.
- **Tours:** `src/components/Tour/` (driver.js). `tours.ts` lists tours per route (home, deck, learn, notes, presets). `TourHost` auto-starts each once, drops steps whose element is missing, stores seen ids in the synced setting `#toursSeen`. Replay via profile menu (`startTourHere`). Closing a tour also marks it seen.
- **Statistics:** local only.

## Master builder, graph and activities (2026-11-06, not checked in a browser)
- `/master/:noteId` (`src/app/master/MasterBuilderView.tsx`): name and status (draft, active, archived), hierarchy level names, sections and entries with drag or arrow reorder, multi-select move and delete, card link chips, card picker with cards in no entry first, bulk "link by text", coverage panel with a fix per problem (add all orphans grouped by tag, unlink dangling, remove empty sections, unsuspend, drop duplicates). Autosave after 700 ms. Entry points: deck page Masters tab, notes explorer view of a master.
- `/graph` (`MasterGraphView.tsx`): SVG graph of masters, cards, note links and entry links; deck filter, pan, zoom, select, open (double click), add or remove a link across decks. Pure layout in `src/logic/master/graph.ts`, no new dependency.
- Activities (`src/logic/master/activities.ts`): recall sweep (suggested rating only; "study missed today" moves due dates only), gap hunt checklist, weak-spot drill at `/learn/<deck>/weak.<masterNoteId>`.
- Pure ops for the MCP agent: `builderOps.ts` (addOrphanEntries, moveEntry, fixDangling, suggestLinks), `activities.ts` (buildGapChecklist, pickWeakSpots).
