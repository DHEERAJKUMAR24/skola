# Phase 16.1 Implementation Plan: MCP deck paths, pacing and study notes

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** make MCP study respect the learner's daily limits, paused decks and time zone, let tools take deck paths, and add boost, limits tools, helpful notes on responses and an interval preview.

**Architecture:** pure helpers under `src/logic/` (day start in a time zone, boost) shared by the app and the server; a new `src/server/mcpDecks.ts` (paths) and `src/server/mcpLimits.ts` (counting, budgets, tools); the study session stores a per-deck remaining budget (`new_budget jsonb`, one migration) computed once at session start. No deck migration: decks are JSON rows with `subDecks` and `superDecks`.

**Tech Stack:** TypeScript, Vitest (`// @vitest-environment node` + PGlite for server code; jsdom + fake-indexeddb for client code), Dexie, ts-fsrs, Biome.

**Spec:** `docs/spec-phase-16.md` (sections 4.1 to 4.4), `docs/adr/0018-mcp-daily-limits-and-time-zone.md`; roadmap `docs/superpowers/plans/2026-11-07-roadmap.md` (its Global Constraints apply to every task).

## Global Constraints

- No cron, polling or background work; local-first; FSRS policy unchanged.
- Deck names: 1 to 100 characters, must not contain `::`; sibling names that differ only by case are refused (`[deck_name_taken]`).
- MCP errors: `[code] message` (`ManageError` / `StudyError` style).
- `MAX_NEW_CARDS` for `add_cards` stays 50; session `limit` stays a cards-per-session cap (`DEFAULT_LIMIT`, `MAX_LIMIT`).
- Settings keys added: `#timeZone`, `#dailyBoosts`, `#gradingMode` (each in `SettingsValues` and `defaultSettings`, each with an `InfoTip` where the learner sees it).
- Migration file name: `supabase/migrations/20261108000000_study_session_budget.sql` (`ADD COLUMN IF NOT EXISTS new_budget jsonb`); apply before deploying the code.
- Boost applies to exactly one deck; precedence of limits: preset, then boost, then catch-up (Phase 22, not built here).
- **Verify first:** before each task, re-check the files and functions it names (a grep and a read each).

## Review Focus

- A learner in UTC+13 or UTC-12 close to local midnight: server "today" equals the learner's day (tested in Task 1 and Task 7).
- The day of a daylight-saving change: the new-card count still uses one logical day (Task 1).
- A path with an empty segment (`A::::B`), surrounding spaces, or two sibling decks that differ only by case (Task 4).
- A session on a parent deck with sub-decks of different budgets, one of them paused, and `new_limit` omitted, `0` and larger than the sum (Task 6).
- `get_limits` and a session when `#timeZone` was never written: UTC fallback, and the output says so (Task 7, Task 9).
- A boost recorded for a deck that was deleted, or for yesterday: ignored, never an error (Task 8).
